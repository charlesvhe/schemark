# 迭代管理文档仓库

本目录使用 [Schemark](../README.md) 管理迭代（Sprint）的目录结构、文件命名与内容规范。所有约束定义在 `schemark.json` 中，可通过 `schemark valid` 命令自动校验。

---

## 目录结构

```
example/
├── schemark.json                          # 规则定义
├── README.md                              # 本文件
├── <sprint 目录>/                          # 进行中或已结束的迭代
│   ├── assets/                            # markdown需要引用的其他文件，例如 图片、视频等
│   ├── README.md                          # 迭代说明（必须）
│   ├── T0001-xxx.md                       # 任务
│   └── B0001-xxx.md                       # 缺陷
└── archive/                               # 已归档迭代
    └── <sprint 目录>/                      # 结构与上层一致
```

### Sprint 目录命名

**格式**：`<开始日期>-<结束日期>-<版本号>-<迭代名称>`

| 片段 | 含义 | 示例 |
| --- | --- | --- |
| 开始日期 | 迭代计划开始（yyyyMMdd） | `20260201` |
| 结束日期 | 迭代计划结束（yyyyMMdd） | `20260228` |
| 版本号 | 迭代版本 | `v1.0` |
| 迭代名称 | 自由文本 | `支付与订单` |

完整示例：`20260201-20260228-v1.0-支付与订单`

### archive 目录

固定名称 `archive`，内部子目录遵循相同的 Sprint 命名规则，表示已归档的迭代。

## 迭代说明（README.md）

每个 Sprint 目录下**必须**包含一个 `README.md`。

### Frontmatter

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 迭代场景 | string | 否 | 枚举：`缺陷修复` / `简单需求` / `标准需求` / `复杂需求` |
| 迭代负责人 | string | **是** | 格式：`姓名 域账号`，如 `张三 zhangsan` |
| 产品负责人 | string | **是** | 格式同上 |
| 测试负责人 | string | **是** | 格式同上 |
| 实际结束时间 | string | **是** | 日期格式 `yyyy-MM-dd` |

### Body 必须包含的章节

校验仅检查章节标题存在，不限制顺序，允许包含额外章节。

| 章节 | 说明 |
| --- | --- |
| `## 迭代范围` | 本迭代包含的需求与责任人 |
| `## 提测计划` | 各轮次提测安排 |
| `## 知识库回填` | 迭代结束后的知识沉淀跟踪 |
| `## 变更记录` | 迭代过程中的范围或计划变更 |

### 完整示例

> 路径：`20260201-20260228-v1.0-支付与订单/README.md`

```markdown
---
迭代场景: 标准需求
迭代负责人: 张敏 zhangmin
产品负责人: 林菲 linfei
测试负责人: 赵琳 zhaolin

## 任务文件（T 文件）

**文件名格式**：`T<4位编号>-<标题>.md`

### Frontmatter

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 负责人 | string | **是** | 格式：`姓名 域账号`，如 `王浩 wanghao` |
| 预估工时 | number | **是** | 单位：小时，≥ 0 |
| 已投入工时 | number | **是** | 单位：小时，≥ 0 |
| 状态 | string | **是** | 枚举：`进行中` / `完成` / `取消` |
| 标签 | array | 否 | 字符串数组，如 `["后端", "订单"]` |
| 关联内容 | array | 否 | PRD 或 OpenSpec 的相对路径数组 |

### Body

无强制章节要求，正文内容自由组织。

### 完整示例

> 路径：`20260201-20260228-v1.0-支付与订单/T0007-订单CRUD-API.md`

  - 后端

# 订单创建与查询 API

## 接口

- POST /api/orders 创建订单（幂等键）
- GET /api/orders/:id 查询详情
- GET /api/orders 列表（分页、状态过滤）
- POST /api/orders/:id/close 关闭订单

## 关键点

- 创建订单使用 `Idempotency-Key` 头去重
- 查询场景下索引：`(user_id, status, created_at)`
```

## 缺陷文件（B 文件）

**文件名格式**：`B<4位编号>-<标题>.md`

### Frontmatter

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 优先级 | string | **是** | 枚举：`紧急` / `高` / `中` / `低` |
| 严重性 | string | **是** | 枚举：`致命` / `严重` / `一般` / `细微` |
| 提出人 | string | **是** | 格式：`角色-姓名 域账号`，如 `赵琳 zhaolin` |
| 处理人 | string | **是** | 格式：`姓名 域账号` |
| 状态 | string | **是** | 枚举：`待修复` / `待验证` / `拒绝` / `挂起` |
| 引起人 | string | 否 | 格式：`姓名 域账号` |
| 缺陷起因 | string | 否 | 枚举：`编码` / `研发设计` / `测试` / `需求` / `交互视觉设计` / `资源或效果` / `部署` / `文档问题` / `安全问题` / `建议` / `其他` |
| 解决方法 | string | 否 | 枚举：`已修复` / `延迟解决` / `不计划修复` / `临时解决` / `已知问题` / `误报问题` / `无法修复` / `部署问题` / `不再是问题` / `无法复现` |
| 打回原因 | string | 否 | 枚举：`误报的问题` / `设计如此` / `需要更多信息` / `重复提交` |
| 解决版本 | string | 否 | 修复所在版本号 |
| 不通过版本 | string | 否 | 验证不通过的版本号 |
| 重开版本 | string | 否 | 重新打开的版本号 |

### Body 必须包含的章节

| 章节 | 说明 |
| --- | --- |
| `## 重现步骤` | 包含操作步骤、现象、期待结果 |
| `## 修复细节` | 根因分析与修复方案 |

### 完整示例

> 路径：`20260201-20260228-v1.0-支付与订单/B0006-高并发重复下单.md`

```markdown
---
优先级: 紧急
严重性: 致命
提出人: 赵琳 zhaolin
处理人: 王浩 wanghao
引起人: 王浩 wanghao
缺陷起因: 编码
解决方法: 已修复
状态: 待修复
解决版本: v1.0
---

# 高并发下重复创建订单

## 重现步骤

[操作步骤] 压测脚本以同一 `Idempotency-Key` 并发发送 100 次创建订单请求。
[现象] 同一幂等键仍创建出 3 条订单。
[期待结果] 同一 `Idempotency-Key` 在并发场景下只应产生 1 条订单。

## 修复细节

根因：幂等键写入未放在事务起始，存在 race condition。

修复：将 `Idempotency-Key → order_id` 的映射改为唯一索引落库后，再进入下游订单创建逻辑，保证并发请求只能有一条成功落库。
```
